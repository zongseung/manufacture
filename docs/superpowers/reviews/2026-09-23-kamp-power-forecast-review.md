## 딥러닝·통계모형 평가

**현재 Core를 깊은 신경망이라고 부르기는 어렵다.** B4는 순환 평활 백본 + 조건부 Markov-switching Gaussian AR + MC 경로 예측·보정이다. PyTorch와 Adam 사용 자체가 깊은 표현학습을 뜻하지 않는다. IO는 입력에 따른 얕은 파라미터 함수이고 KAN 후보는 B-spline 전이함수다. 깊은 encoder는 명시적 비목표다(`v2:314,405–409`). IO-HMM이라는 구조적 분류는 [원논문](https://papers.nips.cc/paper/1994/hash/8065d07da4a77621450aa84fee5656d9-Abstract.html)과도 맞는다. [KAN 원논문](https://arxiv.org/abs/2404.19756)의 존재가 이번 후보의 성능을 보장하지는 않는다.

**장점:** 복사·결측 마스킹, 동일 fold·입력 조건의 기준선, 상태 의존성과 피크위험을 함께 보려는 설계, 후보 사전등록, B1을 못 이겼을 때 격차를 공개하는 규칙은 타당하다. 데이터 규모를 고려해 encoder를 제외한 판단도 일관적이다. 아래 문제를 고친 뒤 실험으로 확인해야 한다.

1. **보정의 시간순 독립성.** leave-one-fold-out Platt는 f1을 보정할 때 미래 f2–f4 결과를 쓴다. 후속 fold의 기반 모델은 이미 f1 라벨로 학습할 수 있으므로 간접 경로도 있다(`plan:1261,1310–1315`, `v2:865–869`). 현재 방법은 회고적 교차보정으로 명시할 수 있지만 발행시각 기준의 전향적 OOF라는 해석에는 부족하다. 전향적 평가를 하려면 보정 자료도 각 fold train 안에서 생성해야 한다. 이는 FR-54의 의도적 설계 변경이므로 관련 문서와 함께 결정할 항목이다.

2. **결측 AR 우도는 근사다.** 직전 관측이 없으면 상태별 정상분산으로 재시작한다(`plan:1534`, `v2:517`). 평균 0인 단일 상태 AR(1)에서도 Y1 관측·Y2 결측일 때 Y3|Y1의 평균은 φ²Y1, 분산은 σ²(1+φ²)다. 정상분포 재시작은 이 기억을 잃는다. 정확한 주변우도라는 표현을 고치고, 단일 상태 분석해와 비교하는 작은 검사를 둬야 한다. 정확성이 필요하면 결측 동안 잔차 분포를 전파해야 한다.

3. **피크위험 포화는 해결됐다고 볼 수 없다.** 기존 간이 모의실험의 위험 포화 기록(`v2:691`)은 최종 B4 성능은 아니지만 중요한 가설이다. 전일 요약을 넣은 IO가 당일 미관측 공통 충격을 직접 모델링하는 것은 아니다. B4·IO·진단용 re를 날짜별 위험 분산, AUC, 조건부 Brier skill, 일최대 분위수 coverage로 비교해야 한다. 임계값별 보정 확률과 MC 일최대 분위수는 서로 다른 분포에 대응할 수 있으므로 하나의 일관된 보정 분포라고 단정하지 않는다(`plan:1260`).

4. **KAN의 별도 op 계수는 식별되지 않는다.** 가동별 spline 묶음과 별도 op 열을 같이 쓰는데 Σ Bm(q)=1이므로 `op = Σ op·Bm(q)`이다(`plan:2909–2912`). op spline 계수 전체에 상수를 더하고 op 계수에서 빼도 logit과 차분 벌점이 같다. 주 에이전트가 데이터 없는 대수 예제로 재현했다. 별도 op 열을 제거하면 특징 수는 2M+3, K=3·M=12 전이 모수는 162개다. 관련 PRD·v2·테스트 숫자도 같이 바꿔야 한다.

5. **상태와 표본의 해석.** 원 전력의 세 봉우리가 백본 제거 후 잔차의 세 상태를 증명하지는 않는다. 96슬롯을 독립 표본처럼 세면 안 된다. 계획에 이미 있는 K2/K3와 seed·점유율 검사를 우선 사용한다. 단일 상태 AR 비교는 상태의 추가 가치가 여전히 불명확할 때 넣을 최소 진단이다. 깊은 모델 추가보다 이 확인이 먼저다.

6. **우월성 CI의 해석 제한.** 같은 OOF로 여러 후보를 고르고 개별 95% CI를 보고하는 것은 선택 후 평가다. 사전등록·시도 횟수 공개만으로 편향이 제거되지는 않는다. 이 해석은 [Varma–Simon의 선택과 평가 분리 연구](https://linus.nci.nih.gov/techreport/Varma-Simon-CrossValid.pdf)에 따른다. 계획의 bootstrap은 일 내부 의존성은 보존하지만 날짜 간 의존성은 보존하지 않고, `dm_test`는 단순 평균/표준오차 형태다(`plan:1380–1381`). 손실차 자기상관을 확인하고 필요하면 7일 이동블록 민감도를 추가한다. [Diebold–Mariano 원문 안내](https://www.minneapolisfed.org/research/discussion-papers/comparing-predictive-accuracy-i-an-asymptotic-test)를 기준으로 검정 명칭과 가정을 맞춘다. 현재 CI는 개발 게이트로 사용하되 엄밀한 일반적 우월성 주장과 구분한다.

7. **A+는 계획 가용성에 조건부다.** 당일 가동플래그 사용은 사용자 승인 가정이며 문서에도 공개돼 있다(`v2:281`). 다만 과거 플래그는 당일 실현 생산량 합으로 재구성한다(`plan:341`). 이를 미공개 누수로 단정하지 않고, 00:00 계획이 정확히 주어진다는 대리 가정으로 표기한다. 이미 계획된 Protocol A 비교를 보고하고 실제 적용 전 계획 오류에 대한 민감도를 확인한다.

B1은 기본값 100회로 고정하고 B4는 여러 구조를 탐색하므로 결과의 범위는 우선 **이 고정 B1 설정 대비**다. 일반적인 알고리즘 우월성을 주장하려면 B1의 탐색 예산도 논의해야 하지만, LightGBM 튜닝 금지라는 현재 사용자 범위를 임의로 바꾸지는 않는다.

## Astra · Ponytail 코드 구성 권고

계획의 평평한 모듈 구성, 함수 기반 모델 계약, `CondHMM` 하나로 충분하다. 설정 프레임워크·모델 레지스트리 클래스·캐시 계층·예상 크기만 보고 하는 파일 분할은 추가하지 않는다. 우선순위는 R3·R4의 실제 연결 계약이다. 공유 키의 표준 라이브러리 타입 선언은 선택 개선이지 실행 차단 조건은 아니다.

B4-H에서 줄일 수 있는 확실한 계산이 있다. 중심 배열을 만들려고 전체 B1을 full+5개 교차적합, full/inner 각각 학습한다(`plan:2693–2694`). 전체 B1은 최대 42개 booster지만 H가 소비하는 것은 **정렬된 슬롯 분위수 19개의 중앙값**이다(`plan:1092–1094`). 슬롯 분위수 적합·예측 함수를 B1과 H가 공유하면 최대 504→228 booster/외부 fold로 줄일 수 있다. 이는 계획상의 모델 개수 계산이며 실제 시간 단축 측정값은 아니다. τ=0.5 하나로 줄이면 분위수 교차를 정렬한 중앙값과 달라질 수 있어 기존 동일성 요구를 보존하지 못한다.
